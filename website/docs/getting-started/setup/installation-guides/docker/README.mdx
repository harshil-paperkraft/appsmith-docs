## Prerequisites

Before you begin, ensure you have the following prerequisites:

- [Docker](https://docs.docker.com/get-docker/) (version 20.10.7 or later)
- [Docker-Compose](https://docs.docker.com/compose/install/) (version 1.29.2 or later)
- Whitelist `cs.appsmith.com` in your firewall or security group’s outbound rules to ensure Docker can pull required images and dependencies. To verify connectivity after install, see [Verify connectivity to cs.appsmith.com](/help-and-support/troubleshooting-guide/verify-cs-appsmith-connectivity).
- **Host memory**: The default Docker Compose setup runs MongoDB, Redis, and PostgreSQL inside the Appsmith container. Plan for at least **8 GB of RAM** on the host for this all-in-one deployment. If you externalize supporting services, the Appsmith container may need less host memory. See [Infrastructure and capacity planning](/getting-started/setup/infrastructure-sizing).

## Install Appsmith

Follow these steps to install Appsmith:

1. Create a folder named `appsmith` on your machine for deployment and data storage. Navigate to this folder using the `cd` command.

2. Create a `docker-compose.yml` file with:

   ```yaml
   version: "3"
   services:
      appsmith:
        image: index.docker.io/appsmith/appsmith-ee:<version>
        container_name: appsmith
        ports:
            - "80:80"
            - "443:443"
        volumes:
            - ./stacks:/appsmith-stacks
        restart: unless-stopped
   ```

   :::tip Pin the image to a release tag
   Replace `<version>` with a release tag from [Appsmith on GitHub](https://github.com/appsmithorg/appsmith/releases) (for example, `v1.98`). Pinning the image avoids unexpected upgrades when you recreate the container and is recommended for production. If you omit the tag, Docker uses `latest`, which is acceptable for quick local trials but gives you less control over upgrades.
   :::

   The `appsmith-ee` image installs the _Commercial edition_ (recommended), which offers a _free plan_ and the flexibility to upgrade to a paid plan at any point. To install the _Community edition_, replace `appsmith-ee` with `appsmith-ce` in the image name and keep the same `:<version>` suffix in the `image` attribute within the `docker-compose.yml` file.

3. Start the Docker container by using the below command. You may need to use `sudo` if you don't have permission to run `docker-compose`:

   ```bash
   docker-compose up -d
   ```

   This command will download the necessary Docker image if it doesn't exist locally and start the container.

4. Open [http://localhost](http://localhost) and wait for the server to come up. This can take up to 5 minutes. Once the server is up and running, you can access Appsmith at [http://localhost](http://localhost).

5. Fill in your details to create an administrator account.

6. Once you've created an account, you can either start with the free plan or activate your instance with a license key. If you want to generate a license key, sign up on [customer.appsmith.com](https://customer.appsmith.com) to create one, and then proceed to activate your instance using the newly generated license key.

## Troubleshooting

These are the five problems most often seen when starting Appsmith on Docker, with the symptom, the cause, and the fix for each. For errors not covered here, see [troubleshooting deployment errors](/help-and-support/troubleshooting-guide/deployment-errors).

### Container won't start

**Symptom:** The `appsmith` container exits or restarts instead of staying up, and the logs show an error creating the `mongockInitializingBeanRunner` bean, ending in `Unable to invoke Cipher due to bad padding`.

**Cause:** The Appsmith instance can't read the MongoDB data because the encryption settings don't match. This happens when you install Appsmith in a directory that already holds an Appsmith installation, or when you restore a database backup whose encryption parameters differ from the ones in the instance.

**Fix:** Choose one of these options:

- To overwrite the previous installation, delete the `/stacks` folder from the installation directory and run `docker-compose up -d` again.
- To keep the previous installation, create a new installation directory and follow [Install Appsmith](#install-appsmith).
- To keep the restored data, set `APPSMITH_ENCRYPTION_PASSWORD` and `APPSMITH_ENCRYPTION_SALT` in the `docker.env` file to the values you copied during the backup. See [Backup Database](/getting-started/setup/instance-management/backup-and-restore/backup-database).

### Port already in use

**Symptom:** Appsmith services fail to start after installation, and the logs report that ports `80` and `443` aren't open.

**Cause:** Another process is already using port `80` or `443`, so Appsmith can't bind to them.

**Fix:** Choose one of these options:

- Stop the processes using ports `80` and `443`, then start Appsmith again. This only helps if the processes that held the ports are no longer running on them.
- If you can't stop those processes, edit the `ports` entries in `docker-compose.yml` to assign different ports to Appsmith, then restart the instance.

### MongoDB connection fails

**Symptom:** The deployment doesn't complete because Appsmith can't connect to its internal database.

**Cause:** The database service has connection errors, the environment variables for the database configuration are wrong, or the database isn't reachable over the network. If you use an external MongoDB, the replica set may not be initialized or the connecting user may lack the required roles.

**Fix:**

- Check the database service logs for connection errors.
- Verify that the database environment variables are set correctly, such as `APPSMITH_DB_URL`.
- If you use an external database, confirm that it's reachable from the Appsmith server.
- For an external MongoDB, run `rs.initiate()` as an admin user inside the cluster, and give the user Appsmith connects with the `readWrite` and `clusterMonitor` roles. See [External MongoDB TLS connection fails](/help-and-support/troubleshooting-guide/ssl-certificate-errors).

If MongoDB itself won't start after an upgrade to version 5, see [MongoDB Startup Error Post Migration to Version 5](/help-and-support/troubleshooting-guide/deployment-error-guides/mongodb-startup-error-postv5).

### Out of memory

**Symptom:** The backend starts and is then terminated mid-startup, or the instance fails health checks under memory pressure.

**Cause:** The instance is undersized. The default Docker Compose setup runs MongoDB, Redis, and PostgreSQL inside the Appsmith container, and needs at least 8 GB of RAM on the host.

**Fix:**

- Increase the memory available to the host so it meets the minimum of 8 GB of RAM. See [Infrastructure and capacity planning](/getting-started/setup/infrastructure-sizing).
- If you externalize the supporting services, the Appsmith container may need less host memory.
- Collect the server logs for the time of the crash and share them with support. See [How to Get Container Logs](/getting-started/setup/instance-management/how-to-get-container-logs).

### SSL certificate errors

**Symptom:** Certificate errors when Appsmith calls an internal endpoint or a proxy that decrypts SSL, such as `PKIX path building failed: sun.security.provider.certpath.SunCertPathBuilderException: unable to find valid certification path to requested target`.

**Cause:** Appsmith doesn't trust the certificate presented by the endpoint, because the signing CA root certificate isn't in Appsmith's trust store. With automatic SSL through Let's Encrypt, errors come from domain configuration, Let's Encrypt rate limiting, or entries in the Let's Encrypt logs.

**Fix:**

- Add the custom CA root certificate to the `stacks/ca-certs` folder. If the file has a `.pem` extension, rename it to `.crt`. See [Custom CA Root Certificate](/getting-started/setup/instance-configuration/custom-domain/custom-ca-root-certificate).
- Add the issuing CA certificate, not the server's own self-signed certificate. You can extract the chain with `openssl s_client -connect <host>:443 -showcerts`.
- Restart Appsmith so it applies the certificate on startup.
- For Let's Encrypt errors, confirm that the domain name points to the server's IP address, wait if you've hit the Let's Encrypt rate limit, and check the Let's Encrypt logs for the specific error.
